## Nota: **7.5 / 10**

**Justificativa:** Arquitetura sólida, separação de responsabilidades clara, cobertura de testes excelente (1205 unit + 3 E2E), e features de segurança/performance bem pensadas (vault AES-256-GCM, partições isoladas, stall detector, GC daemon). Perde pontos por: **vanilla JS em 12.8k LoC sem TypeScript** (risco de manutenção/refatoração), **renderer monolítico** (app.js 1.7k linhas), **ausência de menção a hardening do Electron** (contextIsolation, sandbox, CSP, preload), **Flash/PPAPI em 2024** (dívida técnica inevitável), e **lacunas em supply-chain security** (audit, pinning, auto-update assinado).

## TOP 5 Melhorias Concretas (impacto real)

| # | Melhoria | Por que importa |
|---|----------|-----------------|
| **1** | **Migrar para TypeScript + ESLint strict** | Elimina classe inteira de bugs em runtime, viabiliza refatoração segura do renderer monolítico, melhora onboarding. ROI imediato. |
| **2** | **Hardening completo do Electron** — `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, CSP rigorosa, preload scripts tipados, `webSecurity: true` | Superfície de ataque crítica: renderer comprometido = acesso ao vault, cookies, IPC. Hoje não há evidência de defesa em profundidade. |
| **3** | **Quebrar `app.js` (1.7k) em modules/features + state management** (ex: Zustand/Redux Toolkit ou signals) | Renderer único vira "god object". Testes de unidade ficam frágeis, coupling alto, debugging doloroso. Modularização permite lazy-loading e code-splitting. |
| **4** | **Plano de migração pós-Flash** — Ruffle (WASM) + fallback nativo, ou wrapper nativo (Tauri/Wails) | Flash/PPAPI é dead end. Ruffle já roda Naruto Online razoavelmente. Preparar agora evita rewrite de emergência quando Electron dropar PPAPI. |
| **5** | **Supply-chain security + Auto-update assinado** — `npm audit ci`, `package-lock` pinned, SBOM, `electron-builder` com code signing + notarization (macOS/Windows), canary channel | Launcher manipula credenciais e roda código remoto (game). Um dependency confusion ou update malicioso compromete usuários. Hoje não há menção a isso. |

## Menções honrosas (próximas da lista)
- **IPC tipado** (schema validation via Zod/Valibot no preload) — evita prototype pollution / message spoofing.
- **Observabilidade** — structured logs + metrics (Prometheus/OpenTelemetry) + crash reporting (Sentry/Electron Crashpad).
- **Testes de contrato IPC** + **fuzzing** do `CryptoService` (key derivation, IV reuse, auth tag verification).
